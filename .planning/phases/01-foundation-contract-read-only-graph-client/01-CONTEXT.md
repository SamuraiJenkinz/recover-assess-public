# Phase 1: Foundation, Contract & Read-Only Graph Client - Context

**Gathered:** 2026-11-15
**Status:** Ready for planning

<domain>
## Phase Boundary

A developer has a CI-enforced scaffold in which the only path to Microsoft 365 is a tested read-only Graph client (`core/graph.py`), and the provisional fact-sheet v1.0 contract is generated from pydantic models. Covers FND-01..07 and GRPH-01..08.

Not in this phase: auth / `TokenProvider` and `doctor` (Phase 2), site resolution, any collector, run orchestration. The Graph client takes a token source as an injected callable so it can be built and tested before auth exists.

<decisions>
## Implementation Decisions

The user approved sign-off 1 and accepted Claude's recommendations for the four remaining gray areas without further discussion. The recommendations are recorded here as locked decisions.

### Sign-off 1: HTTP stack (resolved)
- **D-01:** Use `httpx2` (~=2.16) for all outbound HTTP, and the built-in `httpx2.MockTransport` for tests, through one client factory that accepts `transport=`. `httpx` and `respx` are not dependencies. This overrides the Step 1 spec's `httpx` / `respx` lines. STATE.md blocker "Sign-off 1" is closed. **Reversibility:** costly. Swapping the stack touches graph.py, the client factory and every Graph test.

### CI and task runner
- **D-02:** CI runs on GitHub Actions in `.github/workflows/ci.yml` with a matrix of `windows-latest` (primary, required) and `ubuntu-latest`, Python 3.12, `uv sync --locked`. Steps: ruff check, ruff format --check, mypy strict, `lint-imports`, pytest (includes the schema-drift and repo-scan tests). No live network in CI. There is no git remote yet. The workflow file is still committed so CI turns on when one is added.
- **D-03:** No Makefile, because `make` is not on a stock Windows 11 machine. The single local gate is a stdlib-only `scripts/check.py`, run as `uv run python scripts/check.py`, which runs the same steps in the same order as CI. CI calls the same script, so the local and CI gates cannot drift. A `--fix` flag runs ruff fix/format. This deviates from the Step 1 spec's layout, which lists a Makefile.
- **D-04:** The deliberate-violation check (success criterion 1) is a test fixture: a set of throwaway modules that break each import contract, checked by running import-linter against them. Contracts must not be weakened to make them pass.

### Fact-sheet v1.0 shape
- **D-05:** Model the **full** provisional v1.0 fact sheet now: envelope, `input`, `site`, `libraries[]`, `lists[]`, `exposure_total`, `ownership`, `sample_candidates`, `sam`, `graph_stats`, `warnings`, plus the FND-05 fields (`privacy`, `collect_limits`, per-section `status`/`reason`, `coverage`, `truncated_reason`, `path_unresolved`, `hash_coverage`, `owners_source`, `last_activity` basis). Every key is required, with `null` where allowed. The status/coverage vocabulary must be able to say "unavailable / not collected / truncated" as distinct from zero. The research's top risk was unknown-versus-zero confusion.
- **D-06:** `schema_version` stays `"1.0"` and is **provisional** until Phase 6 (Collector acceptance, PIL-01). Until then, later phases may refine sections in place, regenerating the schema and golden files in the same commit. From the Phase 6 freeze onward, the semver rule applies: add = minor, rename/remove = major. **Reversibility:** one-way after the Phase 6 freeze, because Steps 2/3 read only fields defined in the schema.
- **D-07:** `schemas/fact_sheet.schema.json` is generated by a script (`scripts/gen_schemas.py`, or a module entry point; the planner chooses which) from `model_json_schema()`. A pytest test regenerates the schema in memory and fails on any difference from the checked-in file. Pin the pydantic minor (~=2.14), because the generated text can change between minors.

### Allow-list ownership
- **D-08:** The Graph allow-list is **packaged and locked**, not operator-editable. Templates live inside the package (for example `src/recover_assess/core/graph_allowlist.yaml` loaded with `importlib.resources`, or a Python constant; the planner chooses) and not in the user-facing `config/` directory. Operator YAML and env have no allow-list key, so `extra="forbid"` rejects one. A test pins the exact template set, so any new endpoint is a reviewed code change, and per the project CLAUDE.md each template carries a Microsoft Learn URL. Rationale: an editable allow-list would make the central trust promise configurable. This deviates from the Step 1 spec's `config/graph_allowlist.yaml`. **Reversibility:** reversible.
- **D-09:** Templates are anchored, per-segment patterns (IDs match one segment, never `.*`), as the research recommends (`ReadOnlyPolicy`). Every absolute `@odata.nextLink` and redirect is checked against host `graph.microsoft.com` and prefix `/v1.0/` before it is followed. Redirects are not auto-followed (`follow_redirects=False`). `/content` and any path under `/beta` are rejected.

### Client-data guard (FND-07)
- **D-10:** The FND-07 repo scan covers the **shippable tree** only: `src/`, `tests/`, `config/`, `schemas/`, `scripts/`, `README.md`, `pyproject.toml`, the example config and `.github/`. It enumerates files with `git ls-files`. `.planning/`, `.claude/` and the two root spec/playbook drafts are excluded from the scan **and** from the portable distribution, because they legitimately name the pilot client. The portable package is the built wheel/sdist plus that tree. The planner must make the sdist include list explicit so planning docs never ship.
- **D-11:** The scan uses only generic, client-neutral rules in-repo: SharePoint hostnames other than reserved example tenants (`contoso`, `fabrikam`); email domains other than `example.com` / `contoso.com`; GUID-shaped strings not in an allowed list of fixture IDs; bearer-token / JWT shapes; and the `apis.*` / gateway-style host patterns. Client-specific terms are never written in the repo. An optional external term list is read from a path in an env var (for example `RECOVER_ASSESS_PRIVATE_TERMS_FILE`) and is applied when set: on the developer's machine and in a private CI secret. It is skipped silently when unset.
- **D-12:** Client/gateway settings live only in an external `recover-assess.yaml` outside the repo, located with `--config` / `RECOVER_ASSESS_CONFIG`. The repo ships `recover-assess.example.yaml` with neutral placeholders. `.gitignore` covers `recover-assess.yaml`, `out/`, `*.pem`, `*.pfx` and the token-cache file.
- **D-13:** The two untracked root drafts (`Recover Assessment Collector Build Spec (Step 1).md`, `AI-Ready SharePoint Framework & Enablement Playbook (Draft).md`) stay as working references. Add them to `.gitignore`, or move them under an ignored `docs/private/`. Never commit them to the shippable tree.

### Atomic output for append-only logs (added 2026-11-15, plan revision)
- **D-14:** FND-06 is amended (user-approved 2026-11-15; the original sentence is kept in REQUIREMENTS.md and the amendment appended). Append-only logs (`run.jsonl`) satisfy FND-06 via one write call per complete line followed by a flush, repair of an unterminated tail when the log is opened, and a tolerant reader that skips a trailing partial line. All other output files remain strictly atomic: temp file in the same directory, then replace, with a bounded Windows lock retry. Implemented by Plan 01-02 (run log) and Plan 01-12 (atomic writer). **Reversibility:** reversible. Only `core/log.py` and its tests would change if the log later had to be written another way.

### Claude's Discretion
- Internal shape of the Graph client: one `GraphClient` per run with a shared throttle gate plus a cheap per-site `GraphSession` (semaphore, breaker, deadline), an injected `Clock` for deterministic retry tests, and a `fake_graph` router on `MockTransport`. Follow `.planning/research/ARCHITECTURE.md`.
- Use tenacity for single-request retry, and hand-write the `$batch` re-queue and the 20-throttles-in-60-s breaker.
- Logging: a structured JSONL event logger with a scrub filter. The log-capture test uses a canary token / `downloadUrl` and asserts neither appears.
- Config: a pydantic-settings source order of init (CLI) > env > YAML > defaults. A start-up scan of `RECOVER_ASSESS__*` env vars against known model paths catches typos. A `client_secret` key gets a specific error message.
- Atomic writer: temp file in the same directory, then `os.replace`, with a short retry on Windows `PermissionError` (file lock).
- Exact ruff `select` list. The STACK.md suggestion is the starting point.

</decisions>

<specifics>
## Specific Ideas

- The Step 1 spec's numbers are fixed: 6 retries, 1 s base / 60 s cap full jitter, 5 min per request, 20 throttles in 60 s trips the site breaker (`throttled_out`), `$batch` ≤20, 4 in-flight per site, 2 sites, 30 s connect / 120 s read, HTTP/2 off, `max_items_per_library` 50,000.
- Every request's log line holds: timestamp, site key, method, path template (IDs → `{id}`), status, duration, retry count, request-id. Never bodies, tokens or `downloadUrl` values.
