<objective>
Make the project wheel buildable offline by uv 0.11 and later, and rewrite the README pip fallback so its primary route is the one already proven on a locked-down workstation: pip installs the hash-locked runtime set through the private mirror, and uv builds the project wheel offline with its built-in backend.

Purpose: with the current `[build-system] requires = ["uv_build>=0.13.8,<0.14"]`, uv 0.11.x does not satisfy the floor, so `uv build --offline` falls back to PEP 517 and needs to download uv-build, which the proxy blocks. Relaxing the floor to 0.11 lets uv 0.11.24 build offline (verified by the orchestrator). The README also mis-frames the TLS problem: `UV_SYSTEM_CERTS` exists in uv 0.11+ too; the real blockers are a missing inspection root and uv not being pointed at the mirror.

Output: one pyproject line changed, the build-system equality test replaced by range tests, a new slow wheel-build test, and three README changes (fallback rewrite, mirror-section pip paragraph, TLS framing).

Decision made at plan time (reversible): the `build` dependency group stays `uv_build>=0.13.8,<0.14` (as the brief asks), so `uv.lock` and `requirements/build.txt` do not change. The old test asserted the group string equals `[build-system] requires`; it is replaced by a weaker but sufficient invariant: the group range sits inside the `[build-system]` range and the locked uv-build version satisfies both. The pip route without uv therefore still installs a backend that the project accepts.
